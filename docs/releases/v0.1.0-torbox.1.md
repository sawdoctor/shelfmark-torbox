# v0.1.0-torbox.1 — AirLock and audiobook playback maintenance

This first TorBox-specific prerelease packages the native Shelfmark retention
changes and host maintenance tools used for the existing audiobook deployment.

## TorBox protection and backup

- Request and confirm AirLock for ready audiobook torrent sources, preserving names, tags and alternative hashes. Protection defaults on; quota/API failures stay visible without blocking ready playback imports.
- Retain TorBox sources during audiobook cleanup.
- Protect uniquely matched active library sources and retry protection with the existing ten-minute host timer.
- Copy and verify backup-only vault objects between rclone remotes, without local payload staging, remote deletion, unprotection or replacement of playback links.
- Retain absolute TorBox symlinks across supported audiobook import layouts.

## Legacy library and playback maintenance

- Include the guarded legacy filesystem-view repair that preserves original library paths and per-file Drive links.
- Include backed-up preparation/activation of the sole directory metadata change from five minutes to one hour, with scoped restarts and current-database retention.
- Verify runtime settings and current FUSE bindings despite equivalent replacement container IDs; retain evidence on interrupted/failed runs.
- Explain the persistent setting versus expiring in-memory listings.

The user confirmed successful live activation on 14 October and approximately
two seconds to first audio for *A Tale of Two Cities*. Its metadata had already
been accessed by the helper; this is not a universal cold-start benchmark.

## Publication and updating

Publishing source/images does not reinstall the server's systemd configuration.
Existing host protection/playback repairs remain in place. Native application
completion hooks take effect when Shelfmark is updated to this build.

Versioned images use `ghcr.io/sawdoctor/shelfmark-torbox` and
`ghcr.io/sawdoctor/shelfmark-torbox-lite`, with `0.1.0-torbox.1` and
`v0.1.0-torbox.1` tags. Image availability depends on the Docker publishing
workflow completing. Prereleases do not replace stable `latest` or generic
Shelfmark/legacy image packages. Existing servers can keep their working build.

Retain configuration, library/database volumes, book filenames, progress and
private rollback copies. Legacy Drive books remain on Drive; the TorBox vault
remains a separate backup. No mandatory library rebuild or repeated tests are needed.

Validation: the original application CI/E2E/CodeQL passed for retention;
focused later helper checks covered preservation, runtime equivalence and rollback.
Full application tests were not manually repeated for host-operation documentation.
